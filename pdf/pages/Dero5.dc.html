첫 화면을 가린 안내

Clarity에서 홈 모바일의 탭 1위가 매거진 안내의 닫기(17%)였음
→ 좁은 화면에서는 안내를 띄우지 않고, 입구를 상단 링크로 옮김

눌러도 반응 없는 접수

접수가 안 된다는 피드백인데 서버 요청은 0건. 녹화에서 사진 12장을 넣고 버튼을 10번 넘게 누르는 장면을 확인
→ 접힌 칸 안에만 뜨던 오류를 화면 위 알림으로 올리고, 사진 장수를 미리 안내

검색 유입의 이탈

검색으로 들어온 제품 상세 46세션 중 시뮬레이터 진입 0. 쿠키 안내 모달이 가격과 구매 버튼을 덮고 있었음
→ 안내를 하단 카드로 바꾸고, PC에도 구매 막대를 두고, 제품이 기본 책상에 바로 놓이게 함
  • 사용자 단위 로그: 움짤이 안 올라간다는 제보를 로그로 찾지 못한 일을 계기로, 요청 로그에 사용자 ID와 오류 코드를 남기고 Filebeat → Elasticsearch → Kibana에서 한 사람의 요청을 시간순으로 조회. 이메일과 본문은 남기지 않음
  • 제품 검색용 Elasticsearch를 로그에도 재사용. 로그가 이미 JSON이고 하루 100MB 수준이라 Logstash와 Kafka는 넣지 않음
  • 이 로그로 좋아요 30개부터 막히던 투표(분당 한도 30 → 120회)와 전화번호 입력 검증 오류를 찾아 수정
  • Sentry 오류 수집: 프런트와 백엔드의 5xx, 미처리 예외를 모으고 소스맵을 연결. WebGPU 오류 한 건은 GPU 프로세스가 사라질 때만 난다는 것을 재현해 수정
  • 지금은 Sentry 오류와 사용자 피드백이 이슈로 자동 등록되어 (2)의 루프가 받아 고침
  • 추적 순서: 피드백 기록에서 사용자를 찾고, 서버 로그를 보고, 요청이 없으면 녹화를 확인
  • 수정 뒤 확인: 접수 오류는 배포 당일 새 접수가 성공하고 이벤트 경로의 오류 응답이 0건임을 확인
  • 녹화의 한계: 동의한 방문자만 남아, 모달에서 나간 사람은 데이터에 없음. 그래서 Search Console, 서버 로그와 함께 봄
