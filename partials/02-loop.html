문제 2

개발 일이 전부 사람 손을 거쳤다.

개발 일을 매번 개발자가 책상에 앉아 직접 해야 했다. 시간이 많이 들었다. 에이전트가 쓴 코드를 사람이 일일이 확인하면 사람이 병목이 된다.

  1. 접수
  2. 재현
  3. 수정
  4. 검증
  5. 머지

단계마다 사람이 했다. 걸린 시간을 잰 숫자는 없다.

그래서 정한 원칙 2026-11-22에 지금의 루프를 적용했다.

  1. 저장소 하나2026-11-21에 저장소를 GitHub 하나로 옮겼다.
  2. 절차는 저장소 안의 스킬에스킬은 에이전트가 읽고 따르는 절차 문서다. 예약 실행의 본문은 한 줄이고, 절차는 스킬에 있다.
  3. 단계 신호는 하나단계와 단계 사이를 잇는 신호는 하나만 둔다.
  4. 사람은 위험한 변경만마이그레이션, 인증, 인프라, 결제 변경은 사람이 검토한다.

지금의 루프

신호를 하나 골라 넣는다. 보고 하나가 접수부터 머지까지 간다.

루프의 순서를 글로 적으면 이렇다.

  1. 접수 Sentry 오류와 Slack #dero-feedback 피드백을 Grok Bot이 Linear 이슈로 등록한다.
  2. 판정·재현·수정(Cursor Automations) 보고를 분류하고 실제 화면에서 재현한 뒤 고친다. 수정 전 재현 영상과 수정 뒤 정상 영상이 있어야 이슈가 닫힌다.
  3. 머지 관문 코드를 쓰지 않은 검증자 3명(게이트, 화면, diff)이 따로 확인한다. PASS한 커밋이 PR 최신 커밋과 같을 때만 자동 머지한다. 검증자가 문제를 짚으면 머지하지 않고 다시 고친다.
  4. 사람 몫 마이그레이션, 인증, 인프라, 결제 변경은 사람이 검토한다. 운영 반영도 사람이 지시한다.
