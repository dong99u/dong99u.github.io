    코드를 쓰지 않은 검증자가 통과시킨 커밋이 PR의 최신 커밋과 같을 때만 머지된다.

    2026-11-22 첫 판 · 11-24까지 지금 구성

    스크롤

    의도 문서부터 쓰는 절차는 관리되지 않았다.

    181/ 209개

    2026-11-22, 의도 문서 209개 중 181개가 open으로 남아 있었다. 백엔드 테스트 클래스도 433개 중 423개가 CI에서 돌지 않았다.

    개발 일이 전부 사람 손을 거쳤다.

    그래서 에이전트가 검증하고 머지하는 루프를 짰다.

    오류 접수부터 재현, 수정, 검증, 머지까지 에이전트가 맡고 사람은 위험한 변경만 보도록 절차를 짰다. 2026-11-22에 첫 판을 돌렸고, 11-24까지 지금 구성이 됐다.

    네 가지를 정했다.

    원칙내용
    저장소 하나2026-11-21에 저장소를 GitHub 하나로 옮겼다.
    절차는 저장소 안의 스킬에스킬은 에이전트가 읽고 따르는 절차 문서다.
    단계 신호는 하나단계와 단계 사이를 잇는 신호는 하나만 둔다.
    사람은 위험한 변경만마이그레이션, 인증, 인프라, 결제 변경은 사람이 검토한다.

    신호를 하나 넣으면 보고가 이렇게 흘러간다.

    에이전트사람막힘 꾸민 시연이다. 커밋은 A, B로 적었다. 실제 기록은 다음 장부터 있다.

    루프의 순서를 글로 적으면 이렇다.

    1. 접수 Sentry 오류와 Slack #dero-feedback 피드백을 Grok Bot이 Linear 이슈로 등록한다.
    2. 판정·재현·수정(Cursor Automations) 보고를 분류하고 실제 화면에서 재현한 뒤 고친다. 수정 전후 증거(스크린샷 2장씩과 영상)가 PR에 있어야 머지된다.
    3. 머지 관문 코드를 쓰지 않은 검증자 3명(게이트, 화면, diff)이 따로 확인한다. PASS한 커밋이 PR 최신 커밋과 같을 때만 자동 머지한다. 검증자가 문제를 짚으면 머지하지 않고 다시 고친다.
    4. 사람 몫 마이그레이션, 인증, 인프라, 결제 변경은 사람이 검토한다. 운영 반영도 사람이 지시한다.
